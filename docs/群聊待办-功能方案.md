# 群聊待办 — 功能方案

> 版本: v2.1  
> 日期: 2026-06-10  
> 状态: 方案设计阶段  
> 变更: 简化子开关 — 总开关打开后添加/完成/删除默认全部可用，无需单独开关

## 一、功能定位

"群聊待办"是一个轻量级的群聊任务管理工具。群成员通过 @机器人 即可添加、完成、删除待办事项，机器人统一维护待办列表并在被问到时输出。让群聊中的"你帮我记一下""回头提醒我"不再依赖某个人，而是由机器人兜底。

核心场景举例：
- "帮我记一下周五聚餐报名"
- "待办: 提醒大家交周报"
- "把第三项标记为完成"
- "看看现在有哪些待办"

**重要约束**：该功能仅对用户在配置中指定的群聊生效，未选中的群聊即使 @机器人 发送触发词也不会响应待办命令。

## 二、触发词体系

### 2.1 触发词分类总览

触发词按功能类别分为 7 组，每组有独立的匹配逻辑。当一个 @机器人 消息到达时，按优先级从高到低依次匹配，**首次命中即停止**。

| 优先级 | 功能类别 | 匹配逻辑 | 默认触发词 | 所需参数 | 权限 |
|---|---|---|---|---|---|
| 1 | 查看待办 | 消息中**包含**任一触发词（无需额外参数） | `查看待办` `待办列表` `还有什么没做` `还有啥没做` | 无 | 任何人 |
| 2 | 查看已完成 | 消息中**包含**任一触发词（无需额外参数） | `已完成列表` `看看做完了什么` `完成了哪些` | 无 | 任何人 |
| 3 | 查看已删除 | 消息中**包含**任一触发词（无需额外参数） | `已删除列表` `看看删了什么` `删了哪些` | 无 | 任何人 |
| 4 | 清空列表 | 消息中**包含**任一触发词 | `清空已完成` `清空已删除` | 无 | **仅管理员** |
| 5 | 添加待办 | 消息**以触发词开头**（或以 @bot 后第一个词匹配），随后紧跟待办内容 | `记一下` `添加待办` `新建待办` `帮我记` `待办` | 待办文本（必需，不能为空） | 任何人 |
| 6 | 完成待办 | 消息**以触发词开头**（或以 @bot 后第一个词匹配），随后紧跟编号或内容关键词 | `搞定` `做完了` `完成` `完成了` `done` | 编号（必需，不能为空） | 任何人 |
| 7 | 删除待办 | 消息**以触发词开头**（或以 @bot 后第一个词匹配），随后紧跟编号或内容关键词 | `删掉` `删除` `取消` `不要了` | 编号（必需，不能为空） | 任何人 |
| 8 | 恢复待办 | 消息**以触发词开头**，随后紧跟编号 | `恢复待办` `还原` `恢复` | 编号（必需，不能为空） | **仅管理员** |

### 2.2 触发逻辑详解

#### 2.2.1 "包含匹配"（优先级 1-4）

触发词出现在消息的任意位置即视为命中，不需要用户提供额外参数。

```
@机器人 我想看看查看待办有哪些
            ↑ 包含"查看待办" → 命中优先级 1 → 列出当前待办
```

#### 2.2.2 "前缀匹配 + 参数提取"（优先级 5-8）

触发词必须出现在 @机器人 之后的第一段文本位置（去除 @bot 名称后的开头部分），提取触发词之后的内容作为参数。

```
@机器人 记一下 周五聚餐报名
        ─┬── ────┬────
         │       └─ 参数（待办内容）
         └─ 触发词
```

**参数提取规则**：
- 添加类：触发词后面的全部文本作为待办内容。如果为空，机器人提示"请说明要记录什么待办事项，例如：记一下 周五聚餐"
- 完成/删除/恢复类：触发词后面的第一个词作为目标编号。如果为空或无法识别为有效编号，机器人提示"请指定要操作的待办编号，例如：搞定 3"

**编号识别规则**（按顺序尝试）：
1. 纯数字："3" → 第 3 项
2. 中文数字："三"、"第三" → 第 3 项
3. "第N项"格式："第3项"、"第三项" → 第 3 项
4. 内容关键词模糊匹配：当未找到数字时，用剩余文本与待办内容做相似度匹配，唯一匹配时自动定位，多条匹配时列出候选项让用户确认

#### 2.2.3 冲突解决

当一条消息同时匹配多个优先级的触发词时，**高优先级优先**：

```
@机器人 记一下 待办列表 的使用方法
        ─┬──         ──┬──
         │             └─ 优先级 1 触发词"待办列表"
         └─ 优先级 5 触发词"记一下"

→ 优先级 1 > 5 → 按"查看待办"处理，列出当前待办
```

```
@机器人 搞定 删除
        ─┬   ─┬
         │    └─ 优先级 7 触发词"删除"
         └─ 优先级 6 触发词"搞定"

→ 优先级 6 > 7 → 按"完成待办"处理，但因为"删除"不是有效编号 → 提示请指定编号
```

#### 2.2.4 群聊范围检查（最先执行）

在处理任何触发词之前，先检查当前群聊是否在用户配置的生效范围内：

```
if 当前群聊 ∉ 生效群聊列表:
    → 不响应任何待办命令（静默忽略，消息继续走其他路由）
```

### 2.3 触发词自定义

总开关打开后，添加、完成、删除三项核心操作**默认全部可用**，无需额外开启。三类操作各自有独立的触发词列表，用户可在 UI 中分别自定义（添加或删除触发词），但操作本身不可单独关闭。

### 2.4 触发词默认值汇总

```
# ── 添加待办（优先级 5）──
记一下, 添加待办, 新建待办, 帮我记, 待办

# ── 完成待办（优先级 6）──
搞定, 做完了, 完成, 完成了, done

# ── 删除待办（优先级 7）──
删掉, 删除, 取消, 不要了

# ── 查看待办（优先级 1，不可关闭）──
查看待办, 待办列表, 还有什么没做, 还有啥没做

# ── 查看已完成/已删除（优先级 2-3，不可关闭）──
已完成列表, 看看做完了什么, 完成了哪些
已删除列表, 看看删了什么, 删了哪些

# ── 管理命令（优先级 4+8，仅管理员，不可关闭）──
恢复待办, 还原, 恢复
清空已完成, 清空已删除
```

## 三、群内使用方式

### 3.1 输出格式

#### 查看待办列表

当群成员发送 `@机器人 查看待办` 时，机器人回复：

```
当前群待办内容有：

1. 周五晚上7点聚餐，记得报名
2. 提醒张三交本周周报
3. 确认下周团建地点

共 3 项待办。
回复"完成 N"或"删除 N"可操作指定事项。
```

#### 添加待办

当群成员发送 `@机器人 记一下 周五聚餐报名` 时，机器人回复：

```
已添加待办：周五聚餐报名

当前群待办内容有：

1. 确认下周团建地点
2. 周五聚餐报名

共 2 项待办。
```

**触发词不在开头时**（走"包含匹配"路径，不提取参数）：

```
@机器人 帮我记一下 周五聚餐
        ───┬───
           └─ 不匹配任何"前缀"触发词，但"记一下"也不是"包含"型的查看触发词
           → 不命中待办功能，继续走 AI Chat 路由
```

> 设计意图：`记一下`、`搞定` 等操作类触发词必须出现在消息开头，防止日常对话中的偶然提及误触发。而 `查看待办` 等查询类触发词使用"包含匹配"，更宽松。

#### 完成待办

当群成员发送 `@机器人 搞定 2` 时，机器人回复：

```
已将第 2 项标记为已完成：周五聚餐报名

当前群待办内容有：

1. 确认下周团建地点

共 1 项待办。
```

**编号不存在时**：

```
@机器人 搞定 99
→ 机器人: 未找到第 99 项待办。当前共有 3 项待办，请检查编号。
```

#### 删除待办

当群成员发送 `@机器人 删掉 2` 时，机器人回复：

```
已将第 2 项移至已删除：周五聚餐报名

当前群待办内容有：

1. 确认下周团建地点

共 1 项待办。
```

#### 管理员恢复

当管理员发送 `@机器人 恢复待办 2` 时，机器人回复：

```
已将第 2 项恢复：周五聚餐报名

当前群待办内容有：

1. 确认下周团建地点
2. 周五聚餐报名

共 2 项待办。
```

**非管理员尝试恢复**：

```
@普通成员: @机器人 恢复待办 2
→ 机器人: 仅群管理员可以恢复已删除的待办事项。
```

#### 查看已完成列表

```
已完成事项：

1. 提醒张三交本周周报 — 由 @李四 完成于 6月10日 14:30

共 1 项已完成。
```

#### 查看已删除列表

```
已删除事项：

1. 周五聚餐报名 — 由 @王五 删除于 6月10日 11:00

共 1 项已删除。管理员可回复"恢复待办 N"恢复指定事项。
```

#### 群聊未生效时的行为

```
[群聊未被加入待办功能生效范围]

@张三: @机器人 查看待办
  → （静默无响应，消息继续按正常 AI Chat 处理）
  → 机器人不会提示"该群未开启待办功能"，避免干扰
```

## 四、权限模型

| 操作 | 任何人 | 管理员 |
|---|---|---|
| 添加待办 | ✅ | ✅ |
| 完成待办 | ✅ | ✅ |
| 删除待办（移入已删除） | ✅ | ✅ |
| 从已删除恢复到群聊待办 | ❌ | ✅ |
| 清空已完成列表 | ❌ | ✅ |
| 彻底清空已删除列表 | ❌ | ✅ |

管理员由 `.env` 中的 `ADMIN_WXID` 字段指定（与现有管理员体系一致）。

### 权限设计说明

- **任何人都能添加/完成/删除**：降低使用门槛，群里任何人都可以维护待办列表，这样群聊待办才能真正"活"起来。删除不是彻底销毁，只是软删除移入"已删除"列表，有管理员兜底恢复。
- **仅管理员能恢复/清空**：防止恶意恢复或误清空，保持管理员对列表的最终控制权。

#### 群聊选择器交互说明

群聊选择器的实现参考项目现有的触发关键词选择模式，具体细节：

1. **下拉数据源**：从后端获取当前已配置的群聊列表（即 `.env` 中 `WECHAT_GROUPS` 配置的群，或 WCDB 自动发现的群）。下拉框列出所有可用群聊，已选中的置灰不可重复选择。

2. **方框展示样式**：模仿 `FeaturesPanel.jsx` 中触发关键词的 chip 样式——绿色边框圆角方框，内部显示群聊名称，右侧带 × 删除按钮。与关键词 chip 样式完全一致：
   ```
   className="inline-flex items-center gap-1 px-2.5 py-1 bg-brand-green-light 
                border border-brand-green/20 rounded-lg text-[13px] 
                text-brand-green-hover dark:text-brand-green"
   ```

3. **至少保留一个群**：与触发关键词的规则一致——当只剩一个群时，× 按钮置灰不可点击。

4. **默认值**：默认选中全部群聊（`*`），即所有群均生效。用户可手动移除全部群再逐个添加特定群。

5. **"全部群"快捷选项**：下拉框中第一项为"全部群聊（*）"，选中后清空所有单独选择的群并切换为全群模式。当已处于全群模式时，添加任意单独群会自动退出全群模式。

## 六、功能交互细节

### 6.1 编号规则

- 每个群的待办从 1 开始编号，按创建时间升序排列
- 当某项被完成或删除后，编号**不重排**（保持编号稳定性）
- 查看时仅显示当前活跃（未完成、未删除）的待办，编号保持原序号
- 例如：原来有 #1 #2 #3，用户完成 #2 后再查看，显示 #1 #3 — 编号不变
- 同样，已删除和已完成列表中保留原始编号（显示为"#2（原编号）"）

### 6.2 模糊匹配

- 用户输入 `完成 第3项`、`完成 3`、`搞定第三个` 等均能识别编号
- 用户可以通过内容关键词定位，如 `完成 聚餐` 会匹配到内容包含"聚餐"的待办
  - 唯一匹配时直接完成，并回复确认
  - 多条匹配时列出候选项：`找到 2 项匹配的待办：1. 周五聚餐报名 2. 聚餐地点确认。请输入编号操作。`

### 6.3 并发与防重复

- 同一群同一时间仅处理一个待办命令（自然排队）
- 相同内容的待办不允许重复添加（防止多人重复记录同一事项），机器人回复：`待办"XXX"已存在（第 N 项），无需重复添加。`

### 6.4 自动清理

- 已完成事项保留 N 天后自动清理（在功能开关中配置，默认 30 天，设为 0 表示永久保留）
- 已删除事项保留 N 天后自动彻底清理（默认 30 天）

### 6.5 上限控制

- 单个群最多同时存在 N 条活跃待办（在功能开关中配置，默认 50，范围 1-200）
- 达到上限后，机器人回复提示：`当前待办已达上限（50 项），请先完成或删除一些再添加。`

### 6.6 群聊范围生效规则

- 仅在"生效群聊范围"中选中的群才会响应用户的待办命令
- 未选中群中 @机器人 发送待办触发词时，机器人**静默忽略**（不提示"该群未开启"），消息继续走正常路由（可能触发 AI 对话或总结）
- 这样设计避免在未开启的群里产生干扰性提示

## 七、配置参数汇总

### 7.1 参数表

| 参数名 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `todo_enabled` | boolean | `true` | 群聊待办总开关。打开后添加/完成/删除三项操作默认全部可用 |
| `todo_groups` | string[] | `["*"]` | 生效群聊范围，`"*"` 表示全部群 |
| `todo_max_per_group` | number | `50` | 每群最多活跃待办数（1-200） |
| `todo_completed_retention_days` | number | `30` | 已完成保留天数（0=永久） |
| `todo_deleted_retention_days` | number | `30` | 已删除保留天数（0=永久） |
| `todo_add_keywords` | string[] | 见 7.2 | 添加待办触发词 |
| `todo_complete_keywords` | string[] | 见 7.2 | 完成待办触发词 |
| `todo_delete_keywords` | string[] | 见 7.2 | 删除待办触发词 |

### 7.2 触发词默认值

```
# 添加待办
记一下, 添加待办, 新建待办, 帮我记, 待办

# 完成待办
搞定, 做完了, 完成, 完成了, done

# 删除待办
删掉, 删除, 取消, 不要了

# 以下为固定触发词，不在 UI 中自定义
# 查看待办（固定）
查看待办, 待办列表, 还有什么没做, 还有啥没做

# 查看已完成/已删除（固定）
已完成列表, 看看做完了什么, 完成了哪些
已删除列表, 看看删了什么, 删了哪些

# 管理命令（固定，仅管理员）
恢复待办, 还原, 恢复
清空已完成, 清空已删除
```
