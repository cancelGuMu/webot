> 版本: v1.0  
> 日期: 2026-06-10  
> 状态: 方案设计阶段

---

## 一、功能定位

"群聊待办"是一个轻量级的群聊任务管理工具。群成员通过 @机器人 即可添加、完成、删除待办事项，机器人统一维护待办列表并在被问到时输出。让群聊中的"你帮我记一下""回头提醒我"不再依赖某个人，而是由机器人兜底。

核心场景举例：
- "帮我记一下周五聚餐报名"
- "待办: 提醒大家交周报"
- "把第三项标记为完成"
- "看看现在有哪些待办"

## 二、群内使用方式

### 2.1 激活方式

群成员 **@机器人** 并发送包含触发词的文本即可触发。触发词可在功能开关中自定义。

默认触发词和对应行为：

| 触发词（@机器人后发送） | 行为 |
|---|---|
| `查看待办` / `待办列表` / `还有什么没做` | 列出当前群聊待办 |
| `添加待办` / `记一下` / `新建待办` + 内容 | 添加一条待办 |
| `完成待办` / `做完了` / `搞定` + 编号 | 将指定待办标记为已完成 |
| `删除待办` / `删掉` / `取消` + 编号 | 将指定待办移到已删除列表 |
| `恢复待办` + 编号 | **仅管理员**，从已删除恢复到群聊待办 |
| `已完成列表` / `看看做完了什么` | 查看已完成事项 |
| `已删除列表` | 查看已删除事项 |
| `清空已完成` | **仅管理员**，清空已完成列表 |
| `清空已删除` | **仅管理员**，彻底清空已删除列表 |

### 2.2 输出格式

#### 查看待办列表

当群成员发送 `@机器人 查看待办` 时，机器人回复：

```
当前群待办内容有：

1. 周五晚上7点聚餐，记得报名
2. 提醒张三交本周周报
3. 确认下周团建地点

共 3 项待办。
回复"完成 N"或"删除 N"可操作指定事项。
```

#### 添加待办

当群成员发送 `@机器人 记一下 周五聚餐报名` 时，机器人回复：

```
已添加待办：周五聚餐报名

当前群待办内容有：

1. 确认下周团建地点
2. 周五聚餐报名

共 2 项待办。
```

#### 完成待办

当群成员发送 `@机器人 搞定 2` 时，机器人回复：

```
已将第 2 项标记为已完成：周五聚餐报名

当前群待办内容有：

1. 确认下周团建地点

共 1 项待办。
```

#### 删除待办

当群成员发送 `@机器人 删掉 2` 时，机器人回复：

```
已将第 2 项移至已删除：周五聚餐报名

当前群待办内容有：

1. 确认下周团建地点

共 1 项待办。
```

#### 管理员恢复

当管理员发送 `@机器人 恢复待办 2` 时，机器人回复：

```
已将第 2 项恢复：周五聚餐报名

当前群待办内容有：

1. 确认下周团建地点
2. 周五聚餐报名

共 2 项待办。
```

#### 查看已完成列表

```
已完成事项：

1. 提醒张三交本周周报 — 由 @李四 完成于 6月10日 14:30

共 1 项已完成。
```

#### 查看已删除列表

```
已删除事项：

1. 周五聚餐报名 — 由 @王五 删除于 6月10日 11:00

共 1 项已删除。管理员可回复"恢复待办 N"恢复指定事项。
```

## 三、权限模型

| 操作 | 任何人 | 管理员 |
|---|---|---|
| 添加待办 | ✅ | ✅ |
| 完成待办 | ✅ | ✅ |
| 删除待办（移入已删除） | ✅ | ✅ |
| 从已删除恢复到群聊待办 | ❌ | ✅ |
| 清空已完成列表 | ❌ | ✅ |
| 彻底清空已删除列表 | ❌ | ✅ |

管理员由 `.env` 中的 `ADMIN_WXID` 字段指定（与现有管理员体系一致）。

### 权限设计说明

- **任何人都能添加/完成/删除**：降低使用门槛，群里任何人都可以维护待办列表，这样群聊待办才能真正"活"起来。删除不是彻底销毁，只是软删除移入"已删除"列表，有管理员兜底恢复。
- **仅管理员能恢复/清空**：防止恶意恢复或误清空，保持管理员对列表的最终控制权。

## 五、功能交互细节

### 5.1 编号规则

- 每个群的待办从 1 开始编号，按创建时间升序排列
- 当某项被完成或删除后，编号**不重排**（保持编号稳定性）
- 查看时仅显示当前活跃（未完成、未删除）的待办，编号保持原序号
- 例如：原来有 #1 #2 #3，用户完成 #2 后再查看，显示 #1 #3 — 编号不变

### 5.2 模糊匹配

- 用户输入 `完成 第3项`、`完成 3`、`搞定第三个` 等均能识别编号
- 用户可以通过内容关键词定位，如 `完成 聚餐` 会匹配到内容包含"聚餐"的待办（如有多个匹配则提示用户选择）

### 5.3 并发与防重复

- 同一群同一时间仅处理一个待办命令（自然排队）
- 相同内容的待办不允许重复添加（防止多人重复记录同一事项）

### 5.4 自动清理

- 已完成事项保留 N 天后自动清理（在功能开关中配置，默认 30 天，设为 0 表示永久保留）
- 已删除事项保留 N 天后自动彻底清理（默认 30 天）

### 5.5 上限控制

- 单个群最多同时存在 N 条活跃待办（在功能开关中配置，默认 50，范围 1-200）
- 达到上限后，机器人回复提示："当前待办已达上限（50 项），请先完成或删除一些再添加。"

## 六、配置参数汇总

| 参数名 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `todo_enabled` | boolean | `true` | 群聊待办总开关 |
| `todo_max_per_group` | number | `50` | 每群最多活跃待办数（1-200） |
| `todo_completed_retention_days` | number | `30` | 已完成保留天数（0=永久） |
| `todo_deleted_retention_days` | number | `30` | 已删除保留天数（0=永久） |
| `todo_trigger_keywords` | string[] | 见下方 | 触发词列表 |

默认触发词：
```
查看待办, 待办列表, 还有什么没做, 还有啥没做,

恢复待办,
已完成列表, 看看做完了什么,

```

```jsx
              {/* chip list + input */}
            </div>
            <div className="mt-4 p-3 bg-bg-main/60 border border-border-main rounded-xl">
              <p className="text-xs text-text-muted leading-relaxed">
                💡 <strong>群内使用提示：</strong>
                @机器人 <code>查看待办</code> · <code>记一下 xxx</code> · <code>搞定 N</code> · <code>删掉 N</code> · <code>恢复待办 N</code>（管理员）
              </p>
            </div>
          </motion.div>
        )}
      </AnimatePresence>
    </div>
  )
}
```

### 7.3 设计细节

- **配色**：群聊待办的 accent 色建议使用 `#f59e0b`（琥珀色）或新色 `#e8794b`（暖橙色），与任务管理/待办清单的视觉语义一致
- **图标**：使用 `@phosphor-icons/react` 的 `CheckSquare` 图标（与现有图标体系一致）
- **卡片样式**：遵循项目现有的 `bg-bg-card border border-border-main rounded-2xl shadow-sm` 卡片风格
- **标签切换**：参考 `FeaturesPanel` 中 `AnimatePresence mode="wait"` 的页面切换动画

## 九、与现有功能的协同

- **与总结功能**：待办内容可以包含总结的结论，例如"待办: 根据刚才的讨论，确定团建地点为XX公园" — 总结和待办是两个独立通路，不互相干扰
- **与飞书同步**：未来可扩展，将群聊待办自动同步到飞书多维表格的任务列
- **与粘性提及**：如果用户在粘性窗口内触发待办命令，也会正常处理
